# X 未回关置顶扩展设计

日期：2026-08-01

## 背景

X 的 Following 页面没有“未回关”筛选，而且列表采用按滚动加载的方式。用户希望在浏览自己的 Following 列表时，不必逐个寻找“关注了你 / Follows you”标记，就能集中查看没有回关的账号。

## 目标

- 提供可在 Chrome 中“加载已解压扩展”的 Manifest V3 扩展。
- 仅在当前登录用户自己的 `https://x.com/<handle>/following` 页面运行。
- 用户正常向下滚动时，收集已经加载的账号，并将未回关账号集中显示在页面顶部的可折叠面板中。
- 显示已扫描数、未回关数、扫描进度状态和最近扫描时间。
- 将结果按当前账号保存在 `chrome.storage.local`，刷新或再次打开页面后仍可查看。
- 每个结果只提供打开个人主页的入口，由用户自行判断和操作。

## 非目标

- 不自动滚动页面。
- 不自动或批量关注、取消关注。
- 不调用 X API，不拦截或重放 X 的网络请求。
- 不上传账号、关注关系或使用统计。
- 不支持移动端 X App，也不发布到 Chrome Web Store。

## 用户体验

1. 用户在 Chrome 扩展管理页加载本项目目录。
2. 用户登录 X，打开自己的 Following 页面。
3. 页面顶部出现“未回关”工具条，恢复缓存结果并默认开启只读扫描；用户可暂停/继续扫描或清空结果。
4. 用户正常向下滚动 Following 列表；开启扫描时，扩展监听页面中新出现的用户卡片并去重。
5. 没有出现“关注了你 / Follows you”关系标记的卡片进入未回关列表。
6. 用户展开置顶面板查看账号，并可点击账号打开其个人主页。

置顶面板使用独立滚动区域，避免大量结果挤占 Following 页面。面板不会重排 X 自己维护的虚拟列表，因为虚拟列表重渲染会覆盖 DOM 排序。

## 结构

- `manifest.json`：声明 Manifest V3、`storage` 权限、`https://x.com/*` 站点权限和内容脚本。
- `src/core.js`：纯函数，负责路由判断、文本归一化、关系识别、账号去重和缓存数据校验。
- `src/content.js`：监听单页应用路由和 Following 列表 DOM，协调扫描、缓存与界面。
- `src/panel.js`：构建置顶工具条和结果面板，只通过明确的数据接口更新 UI。
- `src/styles.css`：与 X 浅色/深色主题兼容的隔离样式。
- `tests/core.test.js`：覆盖中英文关系标记、路由、去重和缓存校验。
- `README.md`：安装、使用、权限与安全边界说明。

项目同时提供自己的 `AGENTS.md`、`PLAN.md` 和精简 `memory-bank/`，并在 `ai-toys/README.md` 的子项目表中登记，遵循仓库现有的新项目约定。

扩展不需要 background service worker、`tabs` 权限或任何外部域名权限。

## 数据流

1. 内容脚本从侧栏“个人资料”链接识别当前登录账号，并与 URL 中的账号比较；不一致时不扫描。
2. `MutationObserver` 只读取 Following 列表中新出现的用户卡片。
3. 解析器提取昵称、handle、头像、个人主页链接和页面上可见的回关标记。
4. 扫描状态按 handle 去重后写入本地存储。
5. 面板从扫描状态渲染未回关结果，不修改 X 原列表的顺序和按钮。

## 防误判与错误处理

- 首版明确支持简体中文、繁体中文和英文的回关标记；文本先做空白和大小写归一化，并只接受独立整行标记，避免昵称或简介中的相同词语造成误判。
- 如果无法确认当前页面属于登录账号，面板显示原因并保持只读停用。
- 如果 X 页面结构改变、连续三轮各发现至少五个用户卡片但无法可靠提取 handle，显示“页面结构可能已变化”，完成当前批次已有有效结果的保存后停止记录新结果。
- 缓存保存版本号；结构升级时忽略不兼容缓存，不尝试猜测转换。
- 缓存读失败时不以空数据覆盖旧缓存；写入或清空失败时保留当前页面结果、暂停并允许重试。
- 清空结果只删除当前 X 账号的扫描缓存。
- 缓存结果标注扫描时间和“仅包含已滚动加载的账号”，避免把部分结果误认为全量结果。

## 安全边界

- 权限限定为 `storage` 和 `https://x.com/*`。
- 不读取密码、Cookie、私信或输入框内容。
- 不发送网络请求，不包含分析 SDK、远程脚本或遥测。
- 不触发点击、表单提交、滚动、关注或取消关注。
- 源码保持无构建步骤，便于安装前直接检查。

## 验证

- 使用 Node 内置测试运行器验证 `core.js` 的纯逻辑。
- 对所有 JavaScript 运行语法检查，并校验 `manifest.json` 可解析。
- 用保存的中英文用户卡片文本样例验证关系识别与去重。
- 在 X 自己的 Following 页面进行手工验收：路由限制、滚动采集、刷新恢复、清空当前账号缓存、浅色/深色显示。

## 验收标准

- 在自己的 Following 页面滚动后，面板准确显示已扫描账号中的未回关账号。
- 刷新页面后仍能看到当前账号的缓存结果。
- 访问其他人的 Following 页面时不会扫描或混入结果。
- 扩展不会自动滚动或执行任何关注关系操作。
- 扩展代码中不存在外部请求、凭证、遥测或远程脚本。
