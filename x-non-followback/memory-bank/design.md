# X 未回关按钮高亮扩展设计

日期：2026-08-02
状态：当前产品契约；取代 2026-08-01 的可见面板方案

## 背景

X 的 Following 页面没有“未回关”筛选，而且列表采用按滚动加载的方式。用户希望在浏览自己的 Following 列表时，直接看出哪些已关注账号没有显示“关注了你 / Follows you”，同时不让扩展面板遮挡页面。

## 目标

- 提供可在 Chrome 中“加载已解压扩展”的 Manifest V3 扩展。
- 仅在当前登录用户自己的 `https://x.com/<handle>/following` 页面运行。
- 用户正常向下滚动时，静默收集已经加载的账号，并把确认未回关账号的原生 `Following / 正在关注` 按钮显示为橙红色。
- 将结果按当前账号保存在 `chrome.storage.local`，刷新或再次打开页面后可继续用于关系判断。
- 页面不显示扩展面板、徽标、账号列表、暂停、清空或批量操作控件。
- 原生 Following 按钮的点击行为完全由 X 处理，用户自行判断和操作。

## 非目标

- 不自动滚动页面。
- 不自动或批量关注、取消关注。
- 不调用 X API，不拦截或重放 X 的网络请求。
- 不上传账号、关注关系或使用统计。
- 不替换 X 原生按钮，不改变按钮文字、事件监听器、禁用状态或点击区域。
- 不支持移动端 X App，也不发布到 Chrome Web Store。

## 用户体验

1. 用户在 Chrome 扩展管理页加载本项目目录。
2. 用户登录 X，打开自己的 Following 页面。
3. 扩展在页面内静默启动，不显示额外界面。
4. 用户正常向下滚动 Following 列表；扩展只读取 X 已经加载的用户卡片并按 handle 去重。
5. 卡片没有独立的“关注了你 / Follows you / 跟隨你”标记，且原生已关注控件文字能被精确识别时，该控件显示橙红色描边、浅色背景和光晕。
6. 互相关注、关系无法确认或按钮身份无法精确识别的卡片保持 X 原样。
7. 用户如需取消关注，直接操作 X 原生按钮；扩展不代理点击或请求。

扩展不对 X 的虚拟列表排序或重排。X 复用卡片节点、关系文字稍后加载或用户离开 Following 页面时，高亮必须同步更新或清理，不能残留到其他账号。

## 结构

- `manifest.json`：声明 Manifest V3、`storage` 权限、`https://x.com/*` 站点权限和内容脚本。
- `src/core.js`：纯函数，负责路由判断、文本归一化、关系识别、账号去重和缓存数据校验。
- `src/content.js`：监听单页应用路由和 Following 列表 DOM，协调扫描、缓存、高亮与生命周期清理。
- `src/panel.js`：保留既有内部状态控制器接口；根节点由 CSS 隐藏，不向用户展示或接管操作。
- `src/styles.css`：隐藏扩展根节点，并通过专用 `.x-nfb-following-highlight` 类装饰可靠识别的 X 原生控件。
- `tests/`：覆盖核心关系判断、运行时生命周期、权限边界、按钮高亮以及本地真实渲染夹具。
- `README.md`：安装、使用、权限与安全边界说明。

扩展不需要 background service worker、`tabs` 权限或任何外部域名权限。

## 数据流

1. 内容脚本从侧栏“个人资料”链接识别当前登录账号，并与 URL 中的账号比较；不一致时不扫描。
2. `MutationObserver` 只读取 Following 列表中 X 已经加载的用户卡片。
3. 解析器提取昵称、handle、头像、个人主页链接和页面上可见的独立回关标记。
4. 扫描状态按 handle 去重后写入本地存储。
5. 内容脚本先清理卡片旧高亮，再依据最新关系结果精确同步原生 Following 控件的专用 CSS 类。
6. 路由离开、暂停状态、页面结构异常、主节点替换或内容脚本销毁时统一清理高亮。

## 防误判与错误处理

- 支持简体中文、繁体中文和英文的回关标记；文本先做空白和大小写归一化，并只接受独立整行标记，避免昵称或简介中的相同词语造成误判。
- 已关注控件只接受完整文字 `Following / 正在关注 / 已关注 / 正在跟隨 / 跟隨中`；`Follow / 关注 / 跟随` 和模糊文本不高亮。
- 如果无法确认当前页面属于登录账号，扩展保持停用且不留下高亮。
- 如果 X 页面结构连续多轮无法可靠解析，完成当前批次已有有效结果的保存后停止记录新结果并清理高亮。
- 缓存保存版本号；结构升级时忽略不兼容缓存，不尝试猜测转换。
- 缓存读取失败时不以空数据覆盖旧缓存；写入失败时保留当前页面结果并停止扫描。静默模式不显示重试控件，重新加载扩展和页面后重新尝试。
- 缓存结果始终只代表用户已经手动滚动加载过的账号，不能视为完整 Following 列表。

## 安全边界

- 权限限定为 `storage` 和 `https://x.com/*`。
- 不读取密码、Cookie、私信或输入框内容。
- 不发送网络请求，不包含分析 SDK、远程脚本或遥测。
- 不触发点击、表单提交、滚动、关注或取消关注。
- 只对可靠识别的控件添加或移除 CSS 类，不注册新的点击处理。
- 源码保持无构建步骤，便于安装前直接检查。

## 验证

- 使用 Node 内置测试运行器验证关系判断、缓存、运行时生命周期、Manifest 和按钮样式边界。
- 对所有 JavaScript 运行语法检查，并校验 `manifest.json` 可解析。
- 扫描源码，确认不存在网络、tabs、cookies、程序化点击或滚动能力。
- 用本地 X 风格夹具和真实 `getComputedStyle` 验证面板 `display` 为 `none`，且两枚未回关按钮仍高亮。
- 由用户在已登录 Chrome 的真实 Following 页面验收静默扫描和按钮高亮。

## 验收标准

- 在自己的 Following 页面手动滚动后，确认未回关账号的原生 Following 控件明显高亮。
- 页面不出现扩展悬浮面板或额外操作控件。
- 互相关注、无法确认关系或无法确认按钮身份的卡片不高亮。
- 刷新、虚拟节点复用和路由离开时不出现错误残留高亮。
- 访问其他人的 Following 页面时不会扫描或混入结果。
- 扩展不会自动滚动或执行任何关注关系操作。
- 扩展代码中不存在外部请求、凭证、遥测或远程脚本。
