# 架构

## 组件

- `src/core.js`：纯逻辑。识别 Following 路由、个人资料链接和中英文回关标记；解析卡片快照；校验、合并和筛选缓存状态。
- `src/panel.js`：只负责固定面板的 DOM 与交互，不读取 X 页面、不访问存储。
- `src/content.js`：验证“自己的 Following 页面”，读取 X 已加载的用户卡片，协调本地存储、扫描生命周期、面板和原生按钮高亮。
- `src/styles.css`：所有选择器均限定在 `#x-non-followback-root` 下，避免污染 X 页面。

## 数据流

```text
用户手动滚动
  → X 加载 UserCell
  → content.js 生成有限快照
  → core.js 解析并按 handle 去重
  → chrome.storage.local 按当前账号保存
  → panel.js 只渲染 followsBack=false 的账号
```

## 页面生命周期

扩展通过 X 侧栏的 `AppTabBar_Profile_Link` 识别登录账号，并与当前 `/following` URL 比较。只有两者一致才创建运行时和面板。X 单页路由变化时，文档观察器重新检查上下文；离开自己的 Following 页面会断开卡片观察器、写入待保存状态并销毁面板。

用户卡片可能被 X 的虚拟列表复用，因此扫描器用 `WeakMap` 保存“DOM 节点 → 当前内容签名”。节点内容换成新账号或稍后补上回关标记时会重新合并，完全相同的有效内容不会重复写入。X 在同一路由替换 `<main>` 时，运行控制器会断开旧观察器并绑定新节点；尚未出现 `<main>` 只视为加载中。

内容脚本的浏览器入口只负责装配依赖并启动可注入的运行控制器。路由协调、异步启动、列表观察、存储恢复和故障暂停均可在 Node 测试中使用假文档、假时钟和假 `MutationObserver` 验证。

## 页面装饰

每次解析 `UserCell` 时，内容脚本先清除该卡片残留的扩展样式，再根据最新关系结果同步。只有 `followsBack=false` 且控件完整文字精确匹配 `Following / 正在关注 / 已关注 / 正在跟隨 / 跟隨中` 时，才添加 `x-nfb-following-highlight` 类。虚拟节点变成互关账号或暂时无法解析时会移除旧类；暂停、错误停止、清空、主节点替换或离开路由时统一清理。

该类只改变颜色、描边和光晕，不注册事件、不移动控件、不扩大点击区域；点击和取关请求仍由 X 原页面处理。

## 故障边界

- 回关文案必须是卡片文本中的独立整行，避免昵称或简介包含“Follows you / 关注了你”时误判。
- 连续三轮均出现至少五个 `UserCell` 且没有任何可解析 handle 时才暂停扫描；完整处理当前批次，并先安排已有有效结果的保存。
- 缓存带版本和 owner handle；版本或账号不匹配时返回空状态。
- 本地缓存读取失败时不扫描、不写入空状态；写入或删除失败时保留页面内结果、暂停扫描并允许用户点击“继续”重试。
- 缓存状态带运行时 revision，写入按顺序完成；写入期间出现更新时继续补写最新快照，避免旧异步写入反向覆盖新结果。
- 清空动作需要面板内二次点击，只删除当前账号缓存，并保持暂停。
- 面板所有账号数据用 `textContent` 和重建后的 `https://x.com/<handle>` 链接渲染。
