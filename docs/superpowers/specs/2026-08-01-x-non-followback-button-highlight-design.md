# X 未回关按钮高亮设计

日期：2026-08-01  
状态：已获用户批准

## 背景与目标

现有扩展会在用户自己的 X Following 页面中识别已经加载的未回关账号，并集中显示在固定面板。用户还希望直接在 X 原生列表中看出哪些账号未回关，减少在面板和列表之间切换。

本改动只把已确认未回关账号卡片中原有的 `Following / 正在关注` 控件显示得更醒目。控件仍完全由 X 管理，用户自行决定是否点击。

## 非目标与安全边界

- 不自动点击、关注或取消关注。
- 不新增批量操作、快捷取关或确认弹窗代理。
- 不自动滚动，不改变现有扫描范围。
- 不新增权限、后台脚本、X API 调用或外部网络请求。
- 不改变按钮文字、可访问性属性、事件监听器或 X 的业务状态。

## 方案选择

采用“只高亮原生按钮”的方案：给未回关账号的原生 Following 控件增加橙红色描边、浅色背景和光晕。相比整卡染色，它更聚焦、页面噪音更低；相比额外徽标，它直接满足“按钮点亮”的需求。

## 组件与数据流

### 控件识别

`src/content.js` 增加可独立测试的控件识别函数。它只在当前 `UserCell` 内查找 `button` 或 `[role="button"]`，并对可见文字做现有的空白、大小写归一化。首版精确支持英文、简体中文和繁体中文的已关注状态文案，例如 `Following`、`正在关注`、`已关注`、`正在跟隨`、`跟隨中`。

只接受完整控件文字匹配。`Follow / 关注 / 跟随`、菜单按钮和包含额外说明的控件都不会被标记，避免把“尚未关注”按钮或其他操作误当成可取消关注控件。

### 高亮同步

每次扫描卡片时，内容脚本先移除该卡片残留的扩展高亮，再根据最新解析结果同步：

1. 卡片无法解析：保持无高亮，避免虚拟列表复用期间显示旧账号状态。
2. `followsBack === true`：保持无高亮。
3. `followsBack === false` 且找到精确匹配的 Following 控件：给控件增加专用类 `x-nfb-following-highlight`。
4. 未找到可靠控件：面板扫描结果照常保存，但不对卡片做宽泛样式修改。

X 虚拟列表复用节点、关系文案稍后加载或按钮文字变化时，现有 `MutationObserver` 与内容签名机制会重新同步样式。暂停扫描、结构异常停止、清空当前结果、离开自己的 Following 页面或内容脚本销毁时，统一移除所有扩展高亮。

### 样式

`src/styles.css` 只为 `.x-nfb-following-highlight` 定义视觉覆盖：

- 橙红色边框和文字；
- 浅橙红背景；
- 两层轻量光晕；
- 明确的键盘焦点样式；
- 深浅主题均保持足够对比度。

样式不设置 `pointer-events`，不移动控件，不扩大点击区域，也不覆盖 X 的禁用状态。按钮文字保持 X 原样，避免用户误以为扩展已经执行取关。

## 故障与兼容处理

- X 修改 Following 控件文案或结构时，无法可靠识别的按钮保持原样，现有面板和结构异常保护继续工作。
- 高亮同步失败不影响账号解析、缓存和面板结果。
- 只处理当前登录账号自己的 `/following` 页面；其他路由不留下高亮类。
- 选择器限定在扫描到的 `UserCell` 内，不全局修改 X 的其他按钮。

## 测试策略

- 先写失败测试，覆盖英文、简体中文和繁体中文 Following 控件识别。
- 覆盖 `Follow / 关注`、菜单按钮和模糊文本不会被识别。
- 覆盖未回关时添加高亮、互相关注或无效卡片时移除高亮。
- 覆盖同一虚拟节点从未回关账号复用为互关账号时不会残留样式。
- 覆盖暂停、路由离开和运行时停止会清理所有高亮。
- 保持现有安全扫描：源码不得出现程序化 `.click()`、滚动或网络请求。
- 使用本地夹具检查深浅背景下的按钮可见性；真实 X DOM 仍需用户重新加载扩展后验收。

## 验收标准

- 用户手动滚动自己的 Following 页面时，已加载且确认未回关的账号，其原生 Following 控件明显高亮。
- 互相关注、无法确认关系或无法确认按钮身份的卡片不高亮。
- 点击行为与未安装扩展时相同，完全由用户和 X 原页面处理。
- 页面节点复用、暂停或离开页面后不出现错误残留高亮。
- 权限、网络和账号动作安全边界与当前版本一致。
